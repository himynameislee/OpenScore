The attacker's view, open to everyone.

OpenScore is a free, open-source tool that rates an organization's external security the way an attacker sees it. It grades a domain from A to F across eight factors, and every finding comes with its evidence, a command to verify it and the fix.

Get OpenScore on GitHub {% if has_sample %} View the sample report {% else %} Download a release {% endif %}

MIT licensed. Runs on Linux and Windows. No account needed.

Every finding shows its work

A score you can't check is hard to act on. OpenScore attaches the raw response, DNS answer or certificate to each finding, marks the line that triggered it, and tells you how to confirm it yourself and how to fix it.

When something isn't a real problem for you, mark it as a false positive, an accepted risk or a compensating control. It leaves the score, and the report keeps a record of who decided and when to review it.

Eight factors, one grade

Each factor is scored from 0 to 100 and weighted into the overall grade. Names hosted by a SaaS provider are reported but kept out of the score, because the provider controls those settings.

You decide how far it goes

OpenScore has three modes, each one closer to the target than the last. Passive and light run by default. Active checks are for systems you own or have written permission to test.

ModeWhat it doesContact with the targetTo turn it on
PassiveReads DNS and email records, certificate logs, reputation lists and Shodan dataNoneAlways on
LightLoads the home page, reads headers and cookies, checks the TLS certificate and protocolsWhat any visitor sendsAlways on
ActivePort scan, path probes, CORS, nuclei safe templates, testssl.shProbes, inside the scope you set--active, an --authorization reference and a typed scope confirmation

Every active action is written to an audit log. OpenScore finds and documents issues; it never exploits them, guesses credentials or submits forms. How scope and authorization work

Install

OpenScore needs Python 3.11 or later. nmap, nuclei, testssl.sh and subfinder are used when they're installed; without them, OpenScore uses its built-in checks.

Linux

git clone {{ repo }}.git
cd OpenScore && ./install_linux.sh
python3 -m openscore example.com --open

Windows 10 or 11

git clone {{ repo }}.git
cd OpenScore
powershell -ExecutionPolicy Bypass -File .\install_windows.ps1
.\openscore.bat example.com --open

Standalone binary

Download openscore-linux-x64 or openscore-windows-x64.exe, check it against SHA256SUMS, and run it. No Python needed; screenshots in the evidence need the source install.
